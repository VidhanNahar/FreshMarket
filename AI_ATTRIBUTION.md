# AI attribution

FreshMarket was built by Vidhan Nahar and Dhairya Rupani with AI-assisted development. AI tools accelerated implementation, review, debugging, test coverage and documentation; the team remained responsible for product decisions, architecture, security trade-offs, code acceptance and all external actions.

## Tools and assisted work

| Tool | How it was used | Representative files and areas |
| --- | --- | --- |
| **OpenAI Codex** | Assisted with implementation drafts, code review, debugging, edge-case analysis, tests and technical documentation for the core marketplace and sponsor integrations. | Arkiv client and schemas: `src/lib/arkiv/chain.ts`, `src/lib/arkiv/schema.ts`, `src/lib/arkiv/queries.ts`; listing data and lifecycle: `src/services/listing-repository.ts`, `src/services/listing-lifecycle.ts`, `src/services/publish-listing.ts`; buyer and seller UI: `src/components/listings/`, `src/components/seller/`; independent reader: `storefront/src/`; Swarm integration: `src/lib/swarm/`, `src/app/api/swarm/upload/route.ts`, `src/components/swarm/`; ENS services and UI: `src/lib/ens/`, `src/services/ens-*.ts`, `src/app/identity/`; associated tests under `src/__tests__/`; and documentation under `arkiv/` and `ens/`. |

The paths above identify the material areas of assistance rather than claiming that every line in a directory was generated by one tool. Git history, commit messages and co-author trailers provide the finer-grained record.

## What the team did directly

- Chose the marketplace problem, sponsor-track scope, user flows and acceptance criteria.
- Evaluated suggested designs and decided the separation of responsibilities among Arkiv, ENSv2 and Whitechain.
- Reviewed, edited and integrated AI-assisted code instead of accepting generated output blindly.
- Created and controlled the test wallets; decided when to run and authorized the scripts that signed Rabdi, Ethereum Sepolia and Whitechain Sepolia transactions.
- Deployed and verified the contracts, exercised the live application, investigated failures and recorded the resulting transaction evidence.
- Made the final security, UX, documentation and submission decisions.

## How AI-assisted work was verified

- Automated checks and their scope are recorded in [`TEST_REPORT.md`](TEST_REPORT.md).
- Arkiv operations are reproducible and linked in [`arkiv/how-you-use-arkiv.md`](arkiv/how-you-use-arkiv.md).
- ENSv2 registration, resolution and delegation evidence is recorded in [`ENS_QUALIFICATION.md`](ENS_QUALIFICATION.md).
- Whitechain deployments, official-USDT payments, refunds and releases are linked in [`whitechain/README.md`](whitechain/README.md).
- Known risks and claims that remain unverified are stated in [`SECURITY.md`](SECURITY.md) and the README limitations instead of being presented as complete.

AI output was therefore an input to the engineering process, not the source of truth. Tests, source review and public onchain evidence are the basis for the project's claims.
